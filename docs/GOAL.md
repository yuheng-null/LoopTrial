# LoopTrial 首版任务书

交付一个普通开发者可安装、现有 AI Agent 能直接使用的嵌入式测量、标定与控制实验工具。接上工程已有的 UART，用户便可以让 Agent 了解设备、采集信号、在约定范围内调整参数、运行实验、核对结果。优先服务小型 MCU 和学生、工程师手里的现成固件。日常使用不需要专用模型账号或付费 API。

## 一个好工具能帮助 Agent 做什么

第一次见到新设备的 Agent 应能自己回答四个问题：这是哪台设备和哪版固件，它有哪些信号及单位，它允许执行什么实验，怎样判断这次操作成功。针对老工程，给出最小固件接入示例和一份短指南，让 Agent 能从源码找到要暴露的变量、配置或动作，核对采样周期、尺度、方向及单位，并用实际读数验证映射。允许已有协议通过小适配器接入。

提供小而清楚的操作，例如发现能力、读取或设置参数、限时采集、执行已声明动作、查询实验、比较记录。让 Agent 能按目标组合它们，也能一次调用完整实验。不把 PID 字段、车型、必有执行器或设定值作为设备的共同前提。高频采样与动作定时由设备或本地程序承担；Agent 可以稍后查询长实验、恢复会话或取消操作。默认返回紧凑摘要和原始数据的引用，按需提取某段波形。让 Agent 能根据结构化的失败原因选择下一项检查。

例如，用户要求“把右轮调快一点”。如果实测发现输出长期饱和，工具应能返回相应区间和证据，使 Agent 转而比较同指令下两轮的表现。用户提出“这个传感器读数抖”时，同一 Agent 也能先采一段原始信号，比较两种滤波的噪声和延迟。工具有价值的结果也包括保留原配置、发现设备在限幅、或指出缺少判定所需的独立参考。

## 用不同对象检验通用性

| 代表性实验 | 要交付的体验 |
| --- | --- |
| 传感器与信号处理 | 无 PID、无执行器的设备可以直接采集。对同一段含静止与已知变化的输入比较两种滤波配置，量化静止噪声与响应延迟，输出原始波形和差异。说明该方法对实际传感器需要怎样的参考或重复条件。 |
| 测量标定 | 共用上述传感器模型，提供两个已知参考点，求零点与比例系数。用未参与拟合的第三个参考点比较标定前后误差。保存参考量、单位、原始值、系数和验证残差。用户可据此迁移到 ADC 或线性传感器。 |
| 温度等慢过程 | 模拟一个有热惯性和延迟的对象，用相同起始条件比较升温表现、超调及稳态误差。实验运行期间可查询状态，离开再回来能按编号获取结果。自动测试可用模拟时钟。 |
| 电机轮速 | 运行重复的目标转速阶跃，在限定幅度和试验预算内完成读取基线、提出或选择候选、应用、采集、复测、保留或恢复。执行结果要能区分跟踪不良与输出饱和。 |
| 两轮直立 | 从已知可站稳的模拟基线施加可重复的小扰动，联合评价倾角恢复、车轮漂移及输出约束。可以复用前述工具、增加项目描述与评价逻辑，实时稳定控制在设备侧执行。 |

先打通最简单的一条路径，然后用性质不同的对象挑战设计。上述示例可以很小，共用模拟器、命令、MCP 接口、采集与记录代码。用户还应该能照一个短例子新增自己的实验，而无需修改 CLI 或 MCP 服务的核心。其他可扩展用途包括泵压响应、舵机死区和电源负载阶跃；标定需要的标准量、负载或执行器由具体项目提供。

## 交付能力

- **两种连接，一次实验。** USB 转串口和 BLE GATT 共用设备协议；首个 BLE 预设为 BD-BT26，可配置通知及写入特征。相同固件和实验换线后只改连接选项。先握手核实设备与能力。USB 设备端口号和 BLE 广播名用于发现，项目身份由应用层确认。
- **面向人的 CLI 与面向 Agent 的 CLI/MCP。** 安装后可直接运行；提供命令帮助、无交互的结构化输出、清楚的工具输入和退出/错误语义。两种入口调用同一套实现。给出不依赖特定模型的标准 MCP 客户端示例，通过真实 MCP 会话发现工具并运行实验。无需把成千上万条样本塞进对话。
- **一项实验，一份可复核记录。** 可追溯实验编号、对象来源、固件或模型版本、采样时间及单位、激励或参考条件、实际生效配置、约束、原始数据及中止原因。提供离线重算、前后对照和人能直接读懂的曲线。相同输入仍可复核；用新参数会如何响应，应由新试验或明确标识的模型给出。
- **数据和动作可信。** 拆包、并包、应答丢失、采样缺口、断线重连是两种接入的常见问题。重复提交不重复启动同一次试验。区分已发送、已应用和已验证恢复。数据不足或初始工况不可比时报告原因；评价约束与优化目标分别显示。参数默认临时生效，持久化单独表达。固件按具体装置执行超时结束、限幅及回退，保持已有实时控制。
- **真实可接入。** 提供最小 MCU 端实现、可构建的 Blue Pill 双传输示例，以及把上层能力映射到既有工程的说明。一个轻量设备描述足以暴露实际支持的子集。慢采样、快速板端缓存和只读采集可以按需启用，测量本身也应能独立使用。

## 最后怎样验收

1. 在干净环境从实际交付包安装，照 README 完成无硬件快速开始。用外部 CLI 及独立的标准 MCP 客户端走正常入口；模拟没有预置仓库上下文的新 Agent，根据工具描述发现能力、运行实验并查回记录。验证短摘要足以决定下一步，原始证据可取。
2. 跑上表的跨领域示例。用已知响应或独立计算核验关键指标，交付可复现的输入、命令和小型样例。至少展示一次接受候选及一次拒绝或无法判断，证明工具能给出不同结论。观察并记录为新领域增加了哪些适配代码。
3. 让串口路径和 BLE 路径分别处理同一实验，测试分片、重试、断链和设备回读不一致，同时检查最终设备状态与留存记录。用虚拟端点或可控替身即可执行常规回归。通过正常客户端验证长实验中途离开及再次查询。
4. 构建 MCU 示例。条件允许时，在 Blue Pill 上运行板内软件对象并分别用有线、蓝牙做同一实验。仿真、板上模型、物理执行机构分别报告；硬件不可用时完成全部软件交付并说明具体限制。
5. 更新 README 为实际安装及使用指南，交付协议和工程接入说明、CLI/MCP 用法、样例记录、测试及简短验收报告。从干净检出复查安装和关键示例，再将经过检查的项目成果提交、推送到本仓库并核对远端版本。

## 实现者的自主权

根据[复用入口](REUSE.md)选成熟部件。目录、语言、通信协议、算法、命令命名、发布打包和工作顺序由实现者决定。优先降低新设备接入成本、让 Agent 容易验证自己的操作，并用错误或反例检验设计。如果有更短的路径能满足以上用户体验，可以直接替换原设想。从立项基线持续做成可用产品，按工程判断安排修改、测试和复核。
