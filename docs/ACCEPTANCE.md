# 从一句症状到实验结果

**简体中文** · [English](ACCEPTANCE.en.md)

2026-11-22 在 Windows、CPython 3.12.10 上，从工程目录外启动了五组独立的 Codex CLI 0.167.2 对话。每组使用已安装的 LoopTrial 0.1.0 候选 wheel、独立的数据目录和标准 stdio MCP 服务。每次先发送工况或用途，等待 Agent 回复，然后在同一对话仅发送一句症状。该轮开始后没有人工输入。台架环境只指定它连接的模拟设备。用户消息、Agent 的明文决策和应用层工具调用按发生顺序保存在各组 JSONL 中。

## 哪份记录最值得先看

**50 °C 温控。** 早轮是“我们平时用这台温控器在 50 °C 工作。先记住这个工况。”末轮是“升温太慢，帮我调快一点。”Agent 读取设备能力和当前增益，从 20 °C 冷启动测基线，再把“调快”定为 95% 温升时间至少缩短 10%。在得到 60 s 的基线后，它选定 54 s 门槛、基线过冲与尾段误差等硬约束、最多三组候选和两次新试验。设备给出了增益范围，每次写入都返回生效值。[完整双轮对话、工具参数及结果](../evidence/sim/thermal50.jsonl)

**测不动时停止。** 早轮限定轮速 150 rpm、占空比最多 45%、原负载。Agent 从默认增益直接试车。实验 `71adba40457e4b64b85cd4dcfd548dae` 中，输出从 1.52 s 到 8 s 连续顶住 45%，轮速尾段稳定在 66.6 rpm，仍差 83.4 rpm。Agent 结束搜索，原增益 Kp=.003、Ki=.004 仍生效。按当前模拟负载和供给能力，需要增加驱动余量才能继续。独立客户端在 15 s 观察窗也测得同一平台速度。[对话与停止判断](../evidence/sim/motorlimit.jsonl) · [独立 CLI 复验](../evidence/sim/detached-cli.jsonl)

不同温控对话中的百分比门槛由各自 Agent 从基线选定。要比较**相同数值目标**下的候选路径，可看独立客户端的传感器实验。同样要求标准差 ≤.45 kPa、延迟 ≤.36 s、持续到达台阶目标，固定候选规则只改变输入噪声。噪声为 1 kPa 时，α=.274625 已合格。升至 1.35 kPa 后，该候选测得 .504 kPa，客户端继续到 α=.17850625，两次独立验证均通过。[两组相同目标的实测调用](../evidence/sim/repeat-bench.jsonl)

## 标定、中断与其他实验

- **第三参考点。** 5 和 35 kPa 两个参考点各测 50 次，拟合 scale=.924621、offset=−.711422 kPa。第三点 19 kPa 留出。第一次原读数偏差 +2.2623 kPa；写入并换种子重新采样后，验证偏差 +.0345 kPa。两份记录为 `5ff8787fd7474ce2b9aaeee637a26575` 和 `42d6c66e96104c268652ddd057fed82a`。
- **采集中断。** 完整基线 `416c354f238546c38be5b83f82cc43e5` 后，写入 α=.3。注入中断的 `ffb0ae23c55849e3b5c0b55c28b076aa` 仅保留 200/401 个样本，缺少完整比较数据。客户端结束该轮，恢复并回读 α=1、scale=1、offset=0；最后有效判定来自基线。离线复核会对截断文件验哈希并给出 `sample_gap`。
- **轮速和两轮直立。** 正常负载的 90 rpm 阶跃，95% 时间从 5.14 s 改为 3.52 s，第一候选仍超 2 s 门槛。下一候选及两次复测均为 1.86 s。小角度直立模型受 3° 扰动，实验 `053d4d79c75844e4b21d17f7e8556472` 在 1.6 s 恢复，轮轴最大位移 .0923 m，峰值加速度 1.021 m/s²。[独立标准 MCP 工具调用与决策](../evidence/sim/repeat-bench.jsonl)
- **离开后再查。** 独立 CLI 进程提交后台温控阶跃后退出。第二个进程用同一请求键取得原编号 `eb382cc9e77646c9a1d87ef772150e0b`。后续进程查询到完成，取回 361 个样本并离线重算通过。4 s 的等待模拟实际经过时间，波形覆盖 180 s 模型时间。[CLI 参数、编号及返回](../evidence/sim/detached-cli.jsonl)

## 自己复核

在已安装 LoopTrial 的环境中，从本版源码或配套证据取得 `evidence/sim/records.zip`。以下命令只读取可移植文件，无需设备、原开发机、采集数据库或模型账号。任一实验可从索引复制完整编号。[案例与实验编号索引](../evidence/sim/index.json) · [完整 49 份原始记录](../evidence/sim/records.zip)

```sh
python -m zipfile -e evidence/sim/records.zip bench-replay
looptrial review bench-replay/runs/bd747e7f12644248a6d572e62b215829
looptrial review bench-replay/runs/71adba40457e4b64b85cd4dcfd548dae
looptrial wave bench-replay/runs/71adba40457e4b64b85cd4dcfd548dae --start 390 --count 8
```

每个编号目录含 `samples.csv`（带时标的原始采样）、`record.json`（单位、工况、有效参数、评价与 SHA-256）和 `plot.svg`。在工程目录之外，用候选包逐份复核，48 份完整采集均从 CSV 重算一致，1 份预期中断记录通过哈希和行数校验。另用 CSV 直接查找三个温控对话中首次达到“环境温度 + 0.95 × 温升”的样本，与全部 18 次报告的时间一致。要重做标定、轮速、平衡、故障、噪声配对和异步 CLI 流程，可从本版源码运行下列命令，输出目录名须是新的。[可执行实验示例](../examples/repeat_bench.py)

```sh
python examples/repeat_bench.py repeat-01
```

## 实验边界

这些记录的设备版本均为主机模拟器 1.0。确定性热模型两次冷启动的样本可完全相同；传感器复测使用新种子。真实传感器的标定迁移需独立标准量，实体装置的负载、延迟、热容和噪声需要另测。台架链路的结论见硬件报告。[Blue Pill 实物验收与接入](HARDWARE.md)

Codex 验收用已有 ChatGPT 登录。启动时给每个进程指定已安装的 `looptrial-mcp` 和独立 `LOOPTRIAL_HOME`，为本次已授权的模拟工具设置了进程级许可。初次连接尚未配置此许可时，非交互客户端中止，未产生采集记录。配好后五组对话均从头开始。公开日志只保留用户消息、Agent 明文回复及 LoopTrial 工具的输入输出。串口枚举已脱敏，大段波形摘录显示首尾样本，全量数据在编号目录内。固定规则回归由示例 Python 客户端执行。候选 wheel 指纹及采集时 Python 模块指纹在索引中，正式版成品校验值以发布附件为准。[Codex MCP 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)
