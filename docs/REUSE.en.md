# Upstream design references

[简体中文](REUSE.md) · **English**

These sources and official documents were reviewed at project inception. Start by testing the smallest component that can replace work. Depending on target MCU resources, integration cost and the first two examples, reuse may mean taking a dependency, reusing code or supporting an existing protocol. Record adopted projects, versions and purposes in release documentation. When copying upstream source, check licenses of the individual files and any bundled components, and preserve copyright and license notices.

| Need | Implementation to evaluate | Fit and differences |
| --- | --- | --- |
| Runtime measurement and calibration of arbitrary quantities | [Scrutiny Debugger](https://scrutinydebugger.com/guide-introduction.html) provides embedded firmware, readable and writable runtime values, target-triggered capture and a Python SDK. | Candidate backend for existing Scrutiny firmware. Check ROM/RAM cost on small MCUs and supported transports. Devices should be able to participate without a full debug stack. |
| Cross-domain experiments, device descriptions and records | [Bluesky](https://github.com/bluesky/bluesky) and [RunEngine experiment metadata](https://blueskyproject.io/bluesky/main/metadata.html). | Examine how common instructions apply across devices and how to keep context with data. Adopt the parts small MCU projects need. |
| STM32 communications, offline analysis and online workflows | [Automatically-adjust-PID-parameters, reviewed revision](https://github.com/Zw-awa/Automatically-adjust-PID-parameters/tree/067191da1a17). Start with `core/serial_manager.py`, `core/analyzer.py` and the MCU examples. | Includes acknowledgements and F103/G431 examples. The default board example controls a software plant. Check licenses separately for application code and ST/Arm example dependencies. |
| Multiple vehicle descriptions, step metrics and adapters | [DiCAR-LAB, reviewed revision](https://github.com/zhaoxc857/DiCar-LAB/tree/7f1743907a54). Inspect `CAR_LAB/vehicles` and, under `CAR_LAB`, `core/metrics.py` and `core/ble_transport.py`. | Includes BLE, parameter readback, speed and balance configurations. Prefer modules independent of the Qt event loop. The first-order-plus-delay speed model applies only under its assumptions. |
| BLE with a complete STM32 balancing vehicle | [robot-control-prompts tuning script](https://github.com/laigure/robot-control-prompts/blob/3d6e22195642/tools/ble_pid_autotune.py). | Uses FFE0/FFE1, repeats trials and outputs JSON. Initial gains are embedded in the script and scoring emphasizes stationary balancing. Read the target's baseline and choose metrics for each experiment. |
| Connect an existing agent | [Standalone llm-pid-tuner skill](https://github.com/KINGSTON-115/llm-pid-tuner/tree/53343a46c47b/skills/pid-tuning). | Review the treatment of units, controller equations, offline analysis and confirmation. External tools provide the device connection. |
| Agent interface and reviewable metrics | [AlphaHarness MCP experiment interface](https://github.com/Alphabots-8810/AlphaHarness/tree/30892efab7b4). | Targets FRC NetworkTables. Its autotuning demonstration uses a simulated flywheel. Consult it for interface design. |
| Waveform inspection and external MCP comparison | [Serial Studio API](https://github.com/Serial-Studio/Serial-Studio/blob/master/doc/help/API-Reference.md). | Supports serial and BLE characteristic reads and writes. Users can run it independently for manual observation or comparison. |
| Cross-platform device I/O and MCP | [pySerial](https://pyserial.readthedocs.io/en/latest/), [Bleak](https://bleak.readthedocs.io/en/stable/api/client.html), [official MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk). | For Python, reuse drivers, protocol SDK and existing clients first. Handle notification and write characteristics separately for BLE GATT. |
| Trial design and physical module behavior | [WPILib SysId routines](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/system-identification/creating-routine.html) and [BD-BT26 documentation](https://botelvdong.com/courses/Modules/docs/bluetooth/Summary). | Review repeatable motor excitation, data recording and stopping rules. The BD-BT26 default MCU UART is 9600 8N1. Subscribe to FFE1 under service FFE0 and write FFE1 or FFE2. Measure throughput on the actual link. |
