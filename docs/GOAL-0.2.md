# LoopTrial v0.2.0 发布验收任务书

**简体中文** · [English](GOAL-0.2.en.md)

从首版推进到正式 v0.2.0 GitHub Release。沿用首版 CLI/MCP、可移植记录、板端回读和停止机制，回归传感器测量与标定、温控、轮速、平衡。

## 交付人和 Agent 能同时使用的实时无线调参上位机

用户可以在电脑上连接设备、选择信号、看实时波形和单位、查看当前生效参数、手动调参、停止设备支持的实验，并叠加比较基线和候选。优先把这条日常工作流做完整。用户启动界面后，仍然可以只对自己的 Agent 说症状；Agent 通过 CLI 或 MCP 使用同一设备，无需用户关掉上位机、腾出串口、填写表单或逐次批准已授权的操作。纯 Agent、无界面的用法也要保留。

让人和 Agent 看到同一条实验时间轴。能区分命令已发送、设备已生效、独立回读已确认。人在中途改了参数，Agent 要能发现这次变化并判断两轮数据是否仍可比较。断线、重连、取消或恢复时，显示最后确认的设备状态和时间；拿不到新读数时明确标记未知。用实际并发操作和中断验证这些行为。

实时控制、动作限幅和超时保护留在设备侧。持续遥测供人观察，快速瞬态允许在板端带时间戳缓存后取回。根据实际带宽安排采样和显示，测出持续运行时的采样率、主机收到的更新率、间断或缺样，以及参数从发出到确认的时间。界面流畅度不能代替这些测量。

## 把「雷霆之车」接成真正的外部整车实验对象

优先评估 https://github.com/18439114865a-beep/leitingzhiche ，固定上游提交。复核首版之后完成的速度环接入试验，复用有价值的部分。此次核心新增验收是让上游的赛道、相机、巡线和车辆响应共同参与一次完整试跑。尽量保留原模型，通过小适配器和可程序化入口实现复位、重复起跑、运行、停止、取回轨迹和事件。允许用受控浏览器运行原来的 WebGL 视觉链路。可以借鉴 F1TENTH 的 reset/step/终止判定以及 DiCAR-LAB 的指标和参数同步。履行 GPL 与上游许可，公开测试优先使用权利清楚的自绘赛道。

实际启动一个用户自己的 Agent，通过已安装产品的公开 CLI 或标准 MCP，从自然语言走到结论。早轮给出赛道或工况，末轮只说「这辆车过弯太慢，帮我调快一点」，之后撤去人工输入。让 Agent 自行发现能力、读取当前配置、测基线、依据数据定指标和有限预算、选择候选并运行。以按规定路线、按序通过检查点且有效完赛为硬条件，在此前提下优化用时。给出能核查漏点、脱线、抄近路或超时的事件和轨迹。

至少交付一次候选失败后 Agent 自行调整、一次改善后用新试跑重复确认，以及一次因约束、数据不足或预算耗尽而有依据地停止。变更早轮给出的一个工况，保持末轮症状相同，核对实际下发和实验是否随之改变。保留对话、真实工具调用、参数、基线、失败候选、复测编号、轨迹和原始数据。固定脚本可用于回归，另留真实 Agent 自主选参的证据。报告结论限定在试过的路线、工况和预算内。

## 用现有 Blue Pill 验证实际链路，并检验陌生工程的接入成本

使用现有 ST-LINK、PA2/PA3 USB 转串口和 PB6/PB7 的 BD-BT26。烧录前确认目标、完整备份，结束后恢复原固件并校验。通过 USB 和 BLE 分别验证在线观察、临时参数写入与回读、波形取回、复测，以及断线后的状态处理。至少一次在人看实时界面时，让 Agent 通过同一设备会话改参数并验证结果。记录当前接线和波特率下实测能达到什么。若台架当天不可用或无法安全保全原程序，记录具体原因，继续其他工作，并区分历史硬件证据与本版新证据。

以一个首次接入的既有工程检验接入指南。记录从源码找到信号、单位、实际生效参数和动作，通过适配器取得第一条有效波形，究竟要改哪里、花多少工作。外部整车项目可以承担这项验收，但要明确它属于软件接入。没有实车或水池时，按现有条件完成发布；把主机仿真、板上模型、USB/BLE 实物链路、尚待实车或 SRDP 水试验证的结论分开写。

## 按第一次拿到成品的用户验收并正式发布

保留中英双语 README 和使用文档。只把 GitHub 项目网址交给有本地工具权限的 Agent，它应能从首页找到安装方式、启动界面、选择 CLI 或 MCP、连接模拟器并完成第一次实验。提供外部工程接入指南、可重复的整车示例、成品位置、对应源码、构建命令、SHA-256、第三方许可、支持平台和已知限制。

从固定源码提交构建版本化主机安装包、Blue Pill 示例固件和必要的示例资源。在工程目录之外的新环境安装本次实际准备发布的包，只看公开 README，验证上位机启动、无硬件快速开始、独立 MCP 客户端、外部整车试跑和复制实验目录后的离线复核。重点排查只在开发机存在的文件、绝对路径、未声明依赖和浏览器资源。发现问题就修复、重建、重验。通过后创建新标签和正式 GitHub Release，下载公开附件核对哈希与对应提交，核实首页能找到最新版。

最终报告应提供下载与启动命令、人和 Agent 共用无线设备、整车有效提速和自主停止的记录，以及 Blue Pill 实测范围和剩余限制。
